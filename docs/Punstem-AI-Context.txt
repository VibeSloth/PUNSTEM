1. PURPOSE AND CURRENT DIRECTION
Punstem helps students study the actual content of their classes using their
teacher's notes, packets, homework, textbook exercises, and review problems.
It began as timed math and chemistry sprints, then expanded into source-aware
tutoring, personalized practice, rapid recognition drills, saved problems,
reminders, and progress tracking.

The goal is effective, efficient studying: understand a concept, solve a new
problem independently, retain it over time, and then build speed. It should
not be only a speed game or a generic AI problem generator.

New local study mode implementation:

8. GRADING AND EXPLANATION REQUIREMENTS
Math numerical/expression grading uses a safe expression parser, not eval
of arbitrary user JS. Support fractions, equivalent expressions, interval
notation, infinity controls, actual square-root notation and graph inputs.

Graph grading should tolerate small human placement errors while rejecting
the wrong curve. Existing default tolerance is about 0.45 coordinate units;
quarter-unit slips pass, wrong neighboring whole-number values fail. More
than the canonical three points can be valid. Absolute/quadratic/root graphs
must include the essential shape/vertex/endpoint constraints. Piecewise
graphs need the required endpoints and interior points, with correct open
versus closed treatment. Do not restrict valid answers to two hard-coded
point sets or require only the example x values when another valid set works.

Chem numeric grading accepts decimal/fraction/scientific notation and
reasonable rounding; correctly rounded answers should not be diagnosed as
conceptual mistakes. Unit conversions still matter. A key example is
ΔG = ΔH − TΔS: use Kelvin, and convert entropy from J to kJ when ΔH is in kJ.

Feedback must distinguish a known result from a guessed cause. A wrong
final answer alone often cannot establish exactly which reasoning error
occurred. Use "Possible..." or "Check..." unless actual work supports a
diagnosis. Help should show relationships, substitution, units/signs and
steps, then an independent retry—not an overwhelming wall of text.

Difficulty should be meaningfully separated. Existing math records have
level 1/2/3. The new hub maps Easy/Standard/Hard to those exact levels, and
does not silently substitute another level if a pool is empty. Chemistry's
new levels are provisional heuristics: concepts, calculations, multi-step.
Do not advertise these as teacher-validated test difficulty.

- Notebook records for redo reasons and personal reminders.
- Feedback reports and page/problem context.

New /api/study reuses activity_events with kind study_attempt; no new
schema migration was introduced. GET returns only the authenticated user's
latest 5,000 study events. POST validates bounded batches, ignores arbitrary
userId overrides, uses server timestamps and idempotent IDs, and rejects
cross-origin writes. It stores question ID, subject, mode, correctness,
independence, elapsed time and a bounded optional rating—not raw answers.

Existing /api/learning returns the user's latest 2,000 learning attempts;
its records also omit raw responses. The study UI combines these histories
and avoids counting a study event plus its corresponding learning event
twice. Retention schedule does not treat second-attempt success as fully
independent success. Coverage is history-window-limited and says so.

Profiles/admin summaries should include completed new study rounds through
the existing progress endpoint. Existing activity tracking covers usage;
do not equate an open browser tab with active studying without evidence.
